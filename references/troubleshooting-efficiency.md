# COMSOL 报错指南与高效恢复

这份指南用于真实操作受阻时快速恢复，不要求每个正常任务逐项执行。先找到最早失败的层级，再从最低必要阶段继续，避免把导出错误变成一次完整重算。

## 一条恢复主线

```text
保留最后可用 MPH/日志 → 判断失败层 → 读取第一条真实错误 → 只改一个层面 → 从最低必要阶段重试 → 保存后再继续
```

优先区分六层：安装与连接、编译与 API、模型树、求解器、保存、后处理。后面出现的报错常常只是前面错误的连锁结果，不要同时修改物理场、网格和求解器。

## 症状与最低成本处理

| 症状或错误指纹 | 先检查 | 优先处理 | 通常是否需要重算 |
|---|---|---|---|
| 找不到 COMSOL、连接失败、JVM 初始化失败 | `COMSOL_ROOT`、`COMSOL_VERSION`、安装位数、MCP doctor、已有进程 | 绑定同一版本的安装根；非 ASCII 路径问题时换到 ASCII runtime；切换版本后重启 MCP | 否 |
| 许可证 checkout/error | 完整 batch/server 日志、许可产品、残留进程 | 等待或释放自己的已知会话，确认许可模块；不要高频盲重试 | 仅未产生有效解时 |
| Java 编译找不到类、方法或 property | 实际编译器版本、第一条 compiler error、目标版本 API 文档 | 用目标版本的 `comsolcompile`；针对该版本修改 feature/property；确认源码与版本一致 | 否，重新编译即可 |
| 编译器返回 0，但没有生成新 `.class` | `.class` 的存在、修改时间、第一条真实编译输出；源码是否把 feature 属性误当成 Physics 根节点方法 | 按“无新 class”判失败；在目标版本 API 中找到正确节点和 getter/setter。例如 `Migration` 之类的设置不应未经确认就在 Physics 根节点调用 `getBoolean(...)` | 否；这首先是检查适配器/API 错误，不等于 MPH 或物理模型损坏 |
| `.java` 被直接传给 batch | 日志停在 input-file 阶段，Java `main` 未运行 | 先编译生成新鲜 `.class`，再把 `.class` 交给 batch | 否 |
| `AccessControlException`、`FilePermission`、写文件失败 | runtime、prefs、当前工作目录和导出路径 | 先写独立 runtime；将输出限制在允许目录，成功后再复制到交付目录 | 通常否 |
| 节点已创建但物理条件没有生效 | feature tag、启用状态、几何维度、selection 内容 | 重新查看真实模型树；几何改变后重建命名选择并检查物理节点绑定 | 是，若旧解使用了错误选择 |
| `Undefined variable`、空 selection、无可用 dataset | 第一条报错对应的组件、域/边界层级、solution/dataset | 修正变量作用域、选择或数据集身份；已有可信解时只重做后处理 | 取决于错误是否进入求解 |
| `not converged`、NaN/Inf、负值异常 | 首个失败参数/时间点、残差、初值、边界、单位和材料属性 | 先修物理或量纲错误；再考虑分步加载、较小初始步、变量缩放和求解器调整 | 是 |
| 命令 exit code 为 0，但没有结果 | batchlog、class status、完成标记、MPH 和导出是否非空 | 按实际产物判定失败；确认 Java 主流程是否执行和保存 | 仅未保存有效解时 |
| MCP/客户端超时但后台仍计算 | job 状态、COMSOL 进程、日志是否继续增长 | 查询原 job，不重复提交同一求解 | 否 |
| PNG/CSV 导出失败，但 MPH 已保存 | solution、dataset、表达式和写入路径 | 从保存后的 MPH 做 postprocess-only，补建结果树并再次保存 | 否 |
| 磁盘突然增长 | runtime 中 MPH、失败归档、重复副本、求解缓存 | 保留唯一可信模型；大型 MPH 不为每个状态复制一份，优先小日志/清单或同卷链接 | 否 |
| 当前脚本能画图，但与正式图明显不同 | 原数据、数据准备、公共样式依赖、字体和脚本身份 | 在隔离目录重画并比较；缺原始依赖时标记为新实现，不冒充原复现脚本 | 否 |

## 求解器失败时的顺序

先找第一处异常，而不是立即切换求解器：

1. 参数值、单位和数量级是否正确；
2. 域、边界和初始条件是否完整且没有冲突；
3. 材料属性和表达式在全部目标域是否有定义；
4. 网格是否解析几何薄层、尖角和强梯度；
5. 初值是否离目标状态过远，参数扫描是否可从已收敛工况连续推进；
6. 最后才调整非线性方法、变量缩放、阻尼、容差或线性求解器。

一次只改变一个主要层面，并保留最后一个收敛模型。稳定化、伪时间步和过度放宽容差只能作为数值手段，不能用来掩盖错误的方程、边界或单位。

## 保存与断点

长计算最有价值的提效措施是尽早留下可恢复状态：

- 几何/材料/物理配置完成后可保存一个无解模型；
- smoke 或基准工况收敛后立即保存；
- 正式求解完成后先保存包含解的 MPH，再导出 CSV/图片；
- 结果树完成后执行最终保存；
- 后处理失败时从已保存 MPH 恢复，不自动重跑 Study。

## 图件复现的身份底线

“脚本能画出一张图”不等于“它生成了当前正式图”。正式图需要能够追到实际数据、数据准备脚本、绘图入口、公共样式/字体依赖和上游 COMSOL 证据。隔离重画结果若与正式图不一致，先判断是有意改版、依赖缺失还是脚本身份错误；未经判断不要覆盖正式图。

## 什么时候必须重算

以下情况才进入重新求解：模型参数、物理接口、边界、源项、网格或时间窗改变；旧解缺失或损坏；求解日志表明未收敛；结果来自错误 selection/变量；关键输出无法从保存模型重新提取；物理或守恒检查失败。

路径、包装脚本、归档、日志解析、图片导出和排版问题通常不需要重算。它们应从已有模型或数据继续恢复。
